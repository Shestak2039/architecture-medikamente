# Задание 3. Оценка Data Encryption at Rest and In Transit

Сначала классифицируем данные, потом для каждого класса выберем инструменты защиты, средства автоматического контроля и итоговый реестр средств.

## 1. Классификация данных

Чувствительность определена по 152-ФЗ.

| № | Класс | Что входит | Чувствительность | Риск |
|---|---|---|---|---|
| К1 | Медицинские данные | медкарта, анамнез, хронические заболевания, заключения, результаты анализов, сканы | спец. категория ПДн | высокий |
| К2 | ПДн пациента | ФИО, дата рождения, контакты, запись к врачу, согласия | ПДн | высокий в связке с К1, без нее умеренный |
| К3 | Платежи и данные сотрудников | платежи, чеки ККМ, кадры, зарплата | ПДн, финансовые | умеренный |
| К4 | Данные для аналитики | псевдонимизированные данные в сырой и обработанной зонах, обезличенные витрины | ПДн до обезличивания, внутренние после | умеренный, после обезличивания низкий |
| К5 | Ключи и журналы аудита | ключи шифрования, токен-хранилище, пароли, журнал доступа | секретные | критический, через них открываются все остальные классы |

Учет ТМЦ персональных данных не содержит, ему хватает общих мер вроде шифрования дисков.

## 2. Классы, необходимость защиты и инструменты

| Данные | В чем необходимость защиты | Инструменты защиты |
|---|---|---|
| К1 Медицинские данные | Утечка раскрывает диагнозы и ведет к ответственности по 152-ФЗ. Подмена заключения или анализа опасна для лечения | **В покое** шифрование полей AES-256 с ключами из KMS, шифрование хранилища сканов и резервных копий. **При передаче** TLS, лаборатории передается токен вместо ФИО. **При использовании** доступ только лечащему врачу и пациенту, аудит каждого чтения |
| К2 ПДн пациента | Утечка контактов дает мошенничество от имени клиники. По записи к врачу можно понять диагноз, а без согласия обработка незаконна | **В покое** шифрование полей, ПДн хранятся только в реестре пациентов, остальные системы хранят ID. **При передаче** TLS. **При использовании** маскирование контактов для ролей, которым они не нужны |
| К3 Платежи и данные сотрудников | Подмена платежей дает финансовые потери, утечка зарплат нарушает 152-ФЗ в отношении сотрудников | **В покое** шифрование базы 1С и дисков. **При передаче** TLS, ККМ в отдельном сегменте сети. **При использовании** доступ только кассирам и бухгалтерии |
| К4 Данные для аналитики | Вместе с токен-хранилищем псевдонимы превращаются обратно в личности | **В покое** шифрование хранилища, сырая зона хранится 30 дней. **При передаче** TLS. **При использовании** токен-хранилище отдельно от аналитики, отчеты только по обезличенным данным на сервере |
| К5 Ключи и журналы аудита | Ключ рядом с данными обнуляет шифрование, а правка журнала скрывает нарушителя | KMS отдельно от данных, автоматическая ротация ключей. Журнал аудита только на добавление, копия вне основного контура |

## 3. Базовые инструменты, которые добавляем

1. **Шифрование в покое.** Полное шифрование дисков серверов, поверх него шифрование полей К1 и К2 в приложении и шифрование резервных копий.
2. **Шифрование при передаче.** TLS на всех каналах, mTLS с лабораторией и партнерами, VPN между офисом и филиалами.
3. **Управление ключами.** HashiCorp Vault хранит ключи отдельно от данных и сам их ротирует.
4. **Токенизация.** Лаборатория, партнеры и аналитика получают токен вместо ФИО.
5. **Контроль доступа и утечек.** Keycloak с MFA, RBAC и ABAC, DLP на почте и USB.

## 4. Автоматизированный контроль

| Что контролируем | Как |
|---|---|
| Все ли ПДн размечены | регулярное сканирование БД и хранилищ, поля с ПДн без тегов уходят ответственному за ПДн |
| Релизы | проверка в CI, что новые поля с тегом `C3` шифруются и не уходят наружу через API |
| Шифрование и сертификаты | ежедневная проверка, что шифрование дисков и бэкапов включено, автоматическое продление сертификатов |
| Доступ к данным | журнал чтения медданных и алерты на нетипичные действия |
| Сроки хранения | плановое удаление по сроку и по запросу пациента |
