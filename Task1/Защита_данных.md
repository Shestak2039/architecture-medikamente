# Задание 1. Шаг 3. Что можно улучшить

Доработанные диаграммы в `Медикаменте_Data_Flow_Diagrams_to-be.drawio`, номера проблем взяты из `Проблемные_зоны.md`.

## 1. Данные и способы защиты

Конфиденциальные данные шифруются при хранении и передаче. Для ролей, которым реальные значения не нужны, они маскируются. В аналитику уходят только обезличенными.

| Данные | Тег | В покое | При передаче | При использовании и в аналитике |
|---|---|---|---|---|
| Медкарта | `PHI` `C3` | AES-256, ключи отдельно от данных | TLS | видят только лечащий врач и пациент, в аналитику обезличенно |
| Результаты анализов | `PHI` `Клинические данные` `C3` | AES-256 | TLS, лаборатории передается токен вместо ФИО | детерминированная псевдонимизация ID, чтобы связывать анализы одного человека |
| Сканы анкет, договоров и другие файлы пациента | `PHI` `C3` | AES-256, папки по ID вместо `FIO-BD` | TLS | только внутри карточки пациента |
| Базовые ПДн пациента (ФИО, ДР, телефон, email) | `PII` `C2` | AES-256 | TLS | динамическое маскирование контактов для ролей, которым они не нужны |
| Адрес, место работы или учебы | `PII` `C2` | по умолчанию не собирать | TLS | в аналитику не передаются |
| Журнал записи | `PII` `C2` | AES-256 | TLS | в аналитику специализация и время без ID, связка пациент + врач раскрывает здоровье |
| Платежи пациентов | `FIN` `PII` `C2` | шифрование базы | TLS, ККМ в отдельном сегменте сети | для P&L и ABC ФИО зануляется |
| Кадры и зарплаты | `PII` `EMPLOYEE` `C2` | шифрование базы 1С и диска | TLS при отправке отчетности | только бухгалтерия |

Обфускация нужна только для тестовых копий при разработке и миграции.

## 2. Механизм тегирования

Сейчас никакая система не знает, где лежат сведения о здоровье, поэтому каждую меру применяют вручную. С тегами мы сможем задать системе, что шифровать, кому показывать, что маскировать и когда удалять.

### Таксономия

| Ось | Теги |
|---|---|
| Категория | `PII`, `PHI`, `Клинические данные`, `FIN`, `EMPLOYEE` |
| Конфиденциальность | `C3` спец. категория ПДн, `C2` ПДн, `C1` внутреннее, `C0` открытое |
| Этап обработки | `raw`, `processed`, `golden`, `analytics` |
| Обезличивание | `masked`, `pseudonymized`, `anonymized` |
| Жизненный цикл | `retention:<срок>`, `archive`, `delete-requested` |

### Правила тег -> действие

| Условие | Действие |
|---|---|
| `C3` | AES-256, доступ по ABAC (лечащий врач или сам пациент), каждое чтение в журнал аудита |
| `PII` `C2` | шифрование, доступ по RBAC, для остальных ролей маскирование |
| `EMPLOYEE` | доступ только бухгалтерии |
| `analytics` без `anonymized` или `pseudonymized` | загрузка в аналитику блокируется, оповещение безопасности |
| `raw` или истек `retention` | удаление или архив по политике хранения |
| `delete-requested` | блокировка и удаление во всех копиях по Data Lineage |

### Внедрение

1. Сканером обходим общий диск, 1С и ПК аналитика в поисках ФИО, ДР, контактов и медицинских терминов.
2. В новых системах тег задается полю в схеме данных еще при проектировании (Privacy by Design).
3. Доступ привязывается к тегам. В новой системе через Keycloak с RBAC и ABAC.
4. Регулярное сканирование ищет ПДн без тегов, сотрудники проходят обучение.

### Инструменты

Компания маленькая и ПДн должны оставаться в РФ, поэтому крупные облачные платформы (BigID, Informatica, Collibra) не подходят.

- **Сейчас.** Varonis или DLP с поиском по шаблонам, развернутые на своем сервере. DLP сразу закроет запрет на вынос `C3`.
- **В новой системе.** Каталог метаданных с тегами на уровне полей, например Apache Atlas с Apache Ranger (опенсорс).
- **Согласия пациентов.** OneTrust из урока не подходит. Он работает только в облаке без региона в РФ. Поэтому согласия нужно хранить в собственном реестре (ID пациента, вид согласия, дата).

## 3. Меры и инструменты

### По процессам DFD

| Процесс | Меры | Проблемы |
|---|---|---|
| 1. Регистрация | электронная форма с минимумом полей, явные согласия на ПДн и сведения о здоровье, валидация контактов, хронические заболевания вносит врач | E1–E4, T2 |
| 2. Запись на прием | единый журнал в системе, ресепшен не видит медкарту, врач видит только свой журнал | A1, A2, S3, S4 |
| 3. Прием у врача | врач вносит заключение сам без бумаги, медкарта только лечащему врачу, чтение в журнал аудита | A2, B1, T2 |
| 4. Анализы | API с лабораторией по TLS через Apache NiFi, токен вместо ФИО, реестр по ID | T1, S1, S3 |
| 5. Оплата | убрать Excel-дубль, учет только в 1С, ККМ в отдельном сегменте | E5, T4 |
| 6. Бухгалтерия и кадры | база 1С только бухгалтерии, шифрование диска, клиент-серверный режим 1С | A4 |
| 7. Склад | доступ только складу и бухгалтерии | A4 |
| 8. Аналитика | обезличенные выгрузки на сервере вместо копий на ПК, Jupyter на сервере, в озеро только обезличенные данные | F1, F2 |

### Общие меры

| Направление | Меры и инструменты | Проблемы |
|---|---|---|
| Доступ | минимальные привилегии, MFA для `C3`, группы AD сейчас, Keycloak потом | A1–A3 |
| Шифрование в покое | FDE сервера, AES-256 для `C3`, ключи отдельно, в перспективе HSM | S1, S2, A4 |
| Шифрование при передаче | TLS | T1, T4 |
| Аудит | аудит доступа Windows Server, события и алерты в Elastic | B1, B2 |
| Утечки | DLP на почту, USB и облака | A1, F1, T3 |
| Организация | документы оператора ПДн по 152-ФЗ, обучение сотрудников | E3 |
| Резервные копии | зашифрованные копии вне офиса, на серверах в РФ | S2 |

### С чего начинаем

1. Разграничить доступ к диску группами AD, включить аудит и шифрование диска. Это закрывает A1, B1 и S1 без новых систем.
2. Остановить вынос данных. Обезличенные выгрузки для аналитика, DLP на почту и USB.
3. Ввести согласия, сократить анкету, оформить документы оператора ПДн.
4. Разметить файлы тегами, формализовать канал с лабораторией.
5. Остальное заложим в целевой архитектуре задания 2.
